# - Чёткость и прямота в промптах


### 🎯 Главный принцип
**Первая строка промпта — самая важная.** Она задаёт тон всему запросу. Сформулируй её чётко и прямо — и результат улучшится значительно.

---

### ✅ Два ключевых правила

**1. Ясность (Clarity)**
Используй простые слова, без расплывчатых описаний. Говори точно, что тебе нужно.

| ❌ Плохо | ✅ Хорошо |
|---|---|
| "Расскажи мне про те штуки на крышах, которые от солнца работают" | "Напиши три абзаца о том, как работают солнечные панели" |

**2. Прямота (Directness)**
Используй инструкции, а не вопросы. Начинай с глагола действия.

| ❌ Плохо | ✅ Хорошо |
|---|---|
| "Я читал про геотермальную энергию — какие страны её используют?" | "Назови три страны, использующие геотермальную энергию. Включи статистику по каждой." |

---

### 🔑 Формула хорошего промпта

```
[Глагол действия] + [Что создать] + [Ключевые ограничения/контекст]
```

**Пример:**
> *"Сгенерируй одно-дневный план питания для спортсмена с учётом его диетических ограничений."*

Это сразу даёт понять: **что делать** (сгенерировать), **что создать** (план питания), **для кого и при каких условиях** (спортсмен, ограничения).

---

### 💡 Полезные глаголы для старта
`Напиши` · `Создай` · `Сгенерируй` · `Объясни` · `Составь` · `Определи` · `Сравни` · `Проанализируй`

---

> **Главный вывод:** Claude — способный помощник, которому нужна чёткая задача, а не загадка. Начни с глагола, будь конкретен — и получи лучший результат сразу.

# - Being Specific (Будь конкретен)


### 🎯 Главная идея
Чем точнее ты описываешь что хочешь — тем лучше результат. Используй два типа инструкций: **Output Guidelines** и **Process Steps**.

---

### 1️⃣ Output Guidelines — Требования к результату

Список качеств, которым должен соответствовать ответ: длина, формат, стиль, элементы.

**Пример:**
```
Output Guidelines:
- Не более 1000 слов
- Включи сцену, где талант проявляется в действии
- Добавь хотя бы одного второстепенного персонажа
- Тон: драматический
```

---

### 2️⃣ Process Steps — Пошаговые инструкции

Шаги, которые Claude должен пройти **до** финального ответа. Помогает при сложном анализе и многоуровневых задачах.

**Пример:**
```
Process Steps:
1. Придумай 3 таланта, которые создадут напряжение
2. Выбери самый интересный
3. Набросай ключевую сцену с этим талантом
4. Только после этого напиши финальный рассказ
```

---

### 3️⃣ Оба блока вместе — профессиональный промпт

```
Напиши рассказ о персонаже, который открывает скрытый талант.

Output Guidelines:
- Не более 1000 слов
- Включи сцену, где талант проявляется в действии
- Добавь хотя бы одного второстепенного персонажа
- Тон: драматический, с элементами юмора

Process Steps:
1. Придумай 3 таланта, которые создадут напряжение
2. Выбери самый интересный
3. Набросай ключевую сцену
4. Только после этого напиши финальный рассказ
```

---

### 🔑 Когда что использовать

| Блок | Когда применять |
|---|---|
| **Output Guidelines** | Почти всегда — контролирует формат и содержание результата |
| **Process Steps** | Сложный анализ, решения, задачи с несколькими углами зрения |
| **Оба вместе** | В профессиональных промптах — максимальная точность и консистентность |

---

### 💡 Быстрое правило
> Если можешь представить 5 разных ответов на свой промпт — он недостаточно конкретный. Добавь **Output Guidelines** и **Process Steps**!

# - Структурирование промптов с XML-тегами

**Зачем нужны XML-теги?**
Они помогают Claude чётко разграничить инструкции и данные в сложных промптах, особенно когда в них много контента разного типа.

**Как использовать:**
Оборачивайте блоки данных в описательные теги, например:
```
<sales_records> ... </sales_records>
<my_code> ... </my_code>
<docs> ... </docs>
```

**Правила именования тегов:**
- Теги не обязаны быть официальными XML — придумывайте любые
- Чем конкретнее название, тем лучше: `<athlete_information>` лучше, чем `<data>`

**Когда особенно полезно:**
- Большой объём данных или контекста
- Смешанный контент (код + документация, данные + инструкции)
- Промпты с несколькими переменными/блоками
- Нужна особая чёткость разграничений

**Главный принцип:** Чем сложнее промпт, тем ценнее XML-теги — для коротких простых запросов эффект минимален, но для объёмных промптов они критически важны.

# - Providing examples

**Идея:** вместо того чтобы объяснять словами что ты хочешь — просто покажи примеры. Claude поймёт паттерн и воспроизведёт его.

**Структура примера:**
```xml
<sample_input>Oh yeah, I really needed a flight delay!</sample_input>
<ideal_output>Negative</ideal_output>
<!-- Это сарказм, поэтому — Negative -->
```

**One-Shot vs Multi-Shot:** один пример задаёт базовый паттерн, несколько — покрывают разные сценарии и edge cases (сарказм, амбигвити, нестандартный формат).

**Где брать примеры:** из оценок промптов — бери входные данные и ответы с наивысшим баллом, они и есть твой идеальный few-shot материал.

**Чек-лист:**
- XML-теги для чёткой структуры
- Явная пометка: «вот пример и идеальный ответ»
- Объяснение, почему ответ считается хорошим
- Примеры закрывают самые частые ошибки модели

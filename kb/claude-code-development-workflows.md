# Памятка: Типы рабочих процессов (Development Workflows) в Claude Code

## Общий принцип
Claude Code — это не просто инструмент написания кода, а полноценный партнёр на всех этапах разработки. Чем больше контекста и структуры вы предоставляете, тем лучше результат.

---

## 1. Стандартный рабочий процесс (Common Workflow)

**Шаг 1 — Загрузить контекст**
Перед тем как просить Claude что-то создать, найдите файлы в проекте, связанные с нужной функциональностью, и попросите Claude их прочитать и проанализировать.

**Шаг 2 — Попросить составить план**
Не переходите сразу к реализации. Попросите Claude обдумать задачу и создать план. Важно: явно указать *не писать код* на этом этапе.

**Шаг 3 — Попросить реализовать решение**
После утверждения плана — попросить Claude реализовать его. Код будет написан с учётом собранного контекста и плана.

---

## 2. Разработка через тестирование (Test-Driven Development Workflow)

Даёт более надёжный код, так как у Claude есть чёткие критерии успеха.

1. **Загрузить контекст** — показать Claude релевантные файлы проекта
2. **Придумать тест-кейсы** — попросить Claude предложить тесты для новой функциональности
3. **Реализовать тесты** — выбрать нужные тесты и попросить Claude написать их код
4. **Написать код, проходящий тесты** — Claude итерирует реализацию до тех пор, пока все тесты не пройдут

---

## Инициализация проекта (не workflow, но основа)

Команда `/init` — сканирует весь кодовой базы и создаёт файл `CLAUDE.md` с описанием структуры, зависимостей, стиля кода и архитектуры. Файл автоматически используется как контекст во всех последующих разговорах.

**Типы CLAUDE.md:**
- **Project** — общий для всей команды, хранится в репозитории
- **Local** — личные заметки, не попадают в git
- **User** — применяется ко всем вашим проектам

---

## Полезные команды

| Команда | Описание |
|---|---|
| `/init` | Сканирует проект и создаёт CLAUDE.md |
| `/clear` | Очищает историю разговора и контекст |
| `#` | Быстро добавить заметку в CLAUDE.md |
